# 面试参考答案示例

仅在用户明确要求附答案时读取。以下三个示例改写自用户提供的口述答案，展示回答的**语气和展开深度**，不作为其他用户的项目事实。每题保留 `**直接回答**` 与 `**展开说明**` 两部分；段落、列表、代码块及长度随问题调整，不必照搬示例。

## 示例一：解释现有实现及失败边界

### 问题：已有目录时为什么要求 `--force`？它能保证安装安全吗？

**直接回答**

`--force` 解决的是覆盖意图，不保证安装过程安全。当前 CLI 发现目标目录已存在时默认拒绝安装；用户显式传入 `--force` 后才会覆盖。但覆盖是“删除旧目录，再复制新目录”，所以中途失败仍可能让旧版本丢失。

**展开说明**

“允许覆盖”和“失败后能恢复”是两件事。前者只需要在覆盖前检查参数；后者需要安排写入顺序和恢复路径。

当前安装顺序是：

```text
删除旧目录 → 复制新目录
```

假设旧版本已删除，复制新版到一半时磁盘满了，目标目录里可能只剩不完整的新文件。此时 `--force` 已经履行了“用户同意覆盖”的作用，却没有保存可恢复的旧版本。它是覆盖保护机制，不是原子安装机制。

## 示例二：推演尚未实现的改造方案

### 问题：如果要避免覆盖中途把旧版删掉，你会怎样改安装流程？

**直接回答**

如果改造，我会采用“先准备、再切换、最后清理”的流程：先在临时目录完整复制并校验新版，成功后再切换正式目录。这样准备阶段失败时，旧版本仍然可用。

**展开说明**

具体步骤是：

1. 在目标目录所在的文件系统创建唯一临时目录。
2. 把新版复制进去，并校验临时目录。
3. 将旧版目录重命名为备份，再把临时目录重命名为正式目录。
4. 切换成功后清理备份；切换失败时优先尝试恢复备份。

临时目录与正式目录放在同一文件系统，是为了利用重命名操作的原子可见性。但“旧版 → 备份”和“临时目录 → 正式目录”仍是两次操作，不能把整条流程称为完全原子。

例如进程崩溃后，如果发现 `target` 不存在、`backup` 存在、`temp` 也存在，就说明很可能停在旧版已备份、新版尚未切换的阶段。恢复程序应该先识别这个状态并恢复旧版，而不是把备份当作垃圾清掉。改造的关键是让每个中间状态都能被识别和恢复。

## 示例三：说明测试结果的实际证明范围

### 问题：自动化检查全绿，为什么仍可能有用户可见错误？

**直接回答**

检查全绿只能说明现有测试观察到的条件成立。只要输入场景、观察点或判断标准没有覆盖用户实际看到的结果，页面依然可能出错。

**展开说明**

以主题配色为例，如果测试只断言生成的 HTML 包含 `--brand`，即使 CSS 中定义了这个变量却没有任何实际选择器使用它，测试仍会通过；用户在浏览器里看到的颜色却可能不对。

这里的问题不是多写几条相同断言就能解决的，而是观察点停在了生成文件。真正影响用户视图的是浏览器解析 HTML 和 CSS、完成层叠后得到的计算样式。要验证配色，就需要在真实渲染环境中读取目标元素的 computed style，再和预期颜色比较。
