# Resume Bullet Examples

这些示例用于帮助 Resume Generation 学习目标文风：高信息密度、技术机制具体、因果关系清晰、结果可追溯。

> 示例仅用于学习写法。只有当对应事实已存在于用户 Career Profile / Claims 中时，才能复用事实内容。

## 1. AI 页面识别：问题 → 方案 → 结果

> 针对电商页面结构频繁变化、传统爬虫维护成本高的问题，基于 LangChain 构建统一的 AI 页面识别能力，实现页面结构自动识别与数据清洗，每月节约运营人力约 10 PD。

为什么好：

- 有明确问题背景。
- 技术方案具体。
- 结果量化。
- 没有无意义堆技术名词。

## 2. Agent Workflow：链路 → 编排 → 业务闭环

> 对接阿里云 MCP，打通内部 SLS 日志自然语言查询能力；基于 LangGraph 构建“用户反馈 → 意图识别 → 日志检索 → 根因归因”的 Agent Workflow，结合用户反馈、页面链路与异常特征进行问题分类、检索策略选择与诊断路径编排，实现从问题发现到原因定位的自动化闭环。

为什么好：

- 明确展示 Workflow 的阶段结构。
- 不只说“用了 LangGraph”，而是说明 LangGraph 如何参与编排。
- 最后回到业务效果。

## 3. RAG：检索链路优化

> 针对历史问题归因场景优化 RAG 检索链路，通过语义切片与上下文关联构建可检索知识单元，引入查询改写、多查询扩展扩大召回覆盖，并结合向量召回、结果去重与相关性排序优化候选集；对召回结果进行上下文完整性与相关性校验，提升复杂问题场景下的有效召回率与根因定位准确性。

为什么好：

- 以“链路”组织多个技术动作，而不是关键词罗列。
- 每个动作都对应一个检索问题。
- 描述的是工程方法，而不是概念解释。

## 4. Redis 大规模处理：规模 → 方法 → 约束 → 结果

> 面向 17 万页面 Key 的大规模缓存刷新场景，使用 Redis Pipeline + 并发池批量处理，并控制内存峰值与并发规模，保障接口在大数据量下稳定响应；结合增量发布机制，将缓存刷新由全量刷新优化为按变更页面刷新，耗时由 7h+ 缩短至约 5min。

为什么好：

- 有规模数据。
- 说明 Pipeline 为什么存在。
- 同时覆盖资源约束与最终结果。

## 5. 性能专项：测量 → 归因 → 优化

> 基于 Playwright 注入 Event Timing API 自建实验室度量，按加载期、hydration 期、滚动期三段归因定位 hydration 长任务、滚动期长任务与加载期交互排队等核心病灶，并通过状态订阅优化、拆包、图片预解码、延迟调度与视口内挂载完成系统性优化，推动移动端 INP 指标改善约 50ms。

为什么好：

- 先说明如何测量和定位，再说明怎么优化。
- 技术动作之间存在明确因果关系。
- 结果落到性能指标。

## 6. A2A 长任务：状态 → 持久化 → 广播 → 恢复

> 围绕 long-running Task 设计可恢复的异步通信链路，将 Task / Status / Artifact / Message 事件按任务顺序写入 PostgreSQL 快照与事务 Outbox，通过 Redis Pub/Sub 完成跨实例事件广播，并支持 SSE 断线重订阅、任务取消及 Webhook 异步通知。

为什么好：

- 每个技术组件职责清晰。
- 体现长任务场景中的状态、事件、广播和恢复。
- 技术名词组成一条完整架构链，而不是简单枚举。

## 7. 工程工具：工具建设 → 复用 → 效率结果

> 基于 AST 设计并开发 H-Lynx 一键迁移工具，共建 Lynx 迁移文档，将 H5 到 Lynx 的迁移效率提升约 20%，推动核心页面完成迁移并带来首屏 FCP 指标改善。

为什么好：

- 明确工具做什么。
- 明确技术手段 AST。
- 有工程效率与性能结果。

## 8. 低代码事件机制：抽象 → 执行链路 → 工程收益

> 设计并实现低代码事件驱动机制，将组件事件、触发条件与动作配置统一抽象至 Schema，通过事件解析与运行时执行链路支撑组件间交互，降低页面交互逻辑的硬编码成本。

为什么好：

- 第一句就明确 Ownership 和主题。
- Schema 不是孤立技术词，而是说明抽象对象。
- “事件解析与运行时执行链路”体现实现机制。
- 最后说明工程价值。

## 9. Weak → Strong 改写

### Weak

> 负责低代码页面编辑器和事件驱动器能力建设。

问题：

- 没说明具体做了什么。
- 没说明实现机制。
- 没说明解决的问题。

### Strong

> 设计并实现低代码事件驱动机制，将组件事件、触发条件与动作配置统一抽象至 Schema，通过事件解析与运行时执行链路支撑组件间交互，降低页面交互逻辑的硬编码成本。

## 10. 禁止机械模仿事实

学习示例时只能迁移“句式与信息组织方式”。

例如用户只说：

```text
页面编辑、实时预览、Schema
```

不能直接生成：

> 基于虚拟 DOM Diff 与 Web Worker 构建实时预览引擎……

因为这些技术事实没有被用户提供或验证。

应先使用已知事实写候选表达，并针对关键机制继续追问。
